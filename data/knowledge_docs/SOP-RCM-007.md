# Retailer Complaint Intake and Triage SOP

SIMULATION ONLY. Synthetic operating procedure for an academic capstone.

## 1. Trigger

Use this procedure when a verified retailer reports a problem or dissatisfaction about an order, delivery, product, price or prior communication.

## 2. Procedure

1. Record the message, sender, timestamp and duplicate-message check.
2. Send only the fixed receipt acknowledgement.
3. Create a case id and classify the issue as delay, shortage, quality, price, availability, communication, safety or other.
4. Extract only decision-relevant facts with exact spans; mark unverified claims as allegations.
5. Link the order, SKU, dispatch record, stock record or prior case when available.
6. Assign severity and an owner. Escalate safety, payment, privacy and repeated unresolved complaints immediately.
7. Request missing facts using a fixed question; do not ask more than two rounds before triage.
8. Present the evidence and possible next actions to a human reviewer.
9. Record the approved resolution or escalation reason. Do not send a substantive response from this system.

## 3. Prohibited shortcuts

- Promising a new date from an unconfirmed supplier message.
- Treating a complaint as proof that stock is missing without reconciliation.
- Closing a case because the retailer stopped replying.
- Editing the original message or deleting a duplicate link.

## 4. Completion check

The case is complete only when the evidence, owner, decision, approver and closure state are present, or the case is explicitly escalated with a reason.
