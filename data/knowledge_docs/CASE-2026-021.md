# Case Note - Re-quote After Approval

SIMULATION ONLY. Synthetic case note; all identifiers are fictional.

## 1. What happened

A reviewer approved a plan to buy Cooking oil 5 L tins from SUP-002 at the rate in the current state version. Two days later the supplier sent a message: "Rate for 5 L tin revised; please confirm before dispatch." The message contained no delay, so the supplier-delay handler did not read the new rate.

## 2. Why the approval did not silently update

The approval was bound to the plan id, state version and unit rate. The rate change created a new fact but not a new state version. The system did not edit the approved plan, and it did not buy anything. The item sat in the queue until a human re-ran planning against a state that carried the new rate.

## 3. What the reviewer saw

- The original approval, with the old rate and the state version.
- A triage item for the re-quote message, with the quoted text and no interpretation.
- A warning that the approved plan's rate was no longer current.

## 4. What was done

The human updated the state version, re-ran planning, and compared the new plan with the old approval. The new rate raised the total cost by enough to change the ranking against a competing supplier, so the old approval was marked void and a new review item was created.

## 5. What this case exposed

- A price change inside or around a delay is not parsed. This is the highest-value gap in the current slice.
- Approval expiry is a policy statement, not yet an automatic timer. It depends on a human noticing the re-quote.
- The system behaved safely: nothing was purchased at the old rate and nothing at the new rate.

## 6. Lesson

An approval is a snapshot, not a standing permission. If the inputs move, the decision has to move with them.
